# FinTrack — API Design

Base path: `/api/v1`. All request/response bodies are JSON unless noted
(CSV upload is `multipart/form-data`). All monetary fields are JSON
strings (e.g., `"1250.00"`), never JSON numbers, so clients never risk
float precision loss in transit — the server parses them as `Decimal`.

This document defines the contract; it is what the OpenAPI schema
(auto-generated by FastAPI from the same Pydantic models) must match, and
what `tests/api/` is written against.

## 1. Conventions

### 1.1 Authentication
Every endpoint except `POST /auth/register`, `POST /auth/login`,
`POST /auth/refresh`, `POST /auth/forgot-password`,
`POST /auth/reset-password`, `GET /health`, `GET /ready` requires a
`Authorization: Bearer <access_token>` header. Admin-only endpoints
additionally require the authenticated user's `role == ADMIN`.

### 1.2 Standard success envelope
Single-resource responses return the resource directly. List responses
use a consistent pagination envelope:

```json
{
  "items": [ /* resource objects */ ],
  "page": 1,
  "page_size": 20,
  "total": 137,
  "total_pages": 7
}
```

### 1.3 Standard error envelope
```json
{
  "error": {
    "code": "ACCOUNT_NOT_FOUND",
    "message": "The requested account was not found",
    "request_id": "b3f1c2..."
  }
}
```
Validation errors (422) additionally include a `details` array of
`{field, message}` objects.

### 1.4 Common status codes
`200` OK · `201` Created · `202` Accepted (async processing) · `204` No
Content (delete/archive) · `400` bad request/business rule violation ·
`401` unauthenticated · `403` forbidden (role-based, not ownership — see
§1.5) · `404` not found (including cross-user ownership misses) · `409`
conflict (duplicate/uniqueness) · `422` validation error · `429` rate
limited · `500` internal error.

### 1.5 Ownership errors return 404, not 403
Per `security-architecture.md` §2, requesting another user's resource by
ID returns `404 RESOURCE_NOT_FOUND`, identical to a genuinely
nonexistent ID. `403` is reserved for role-based denial (e.g., a USER
calling an admin-only endpoint).

### 1.6 Pagination & filtering query params
List endpoints accept `page` (default 1), `page_size` (default 20, max
100), and endpoint-specific filters, documented per endpoint below.
Sortable endpoints accept `sort_by` and `sort_dir` (`asc`/`desc`).

### 1.7 Idempotency
Endpoints marked **[Idempotent-Key]** accept an optional
`Idempotency-Key` request header; see `caching-strategy.md` §4.

## 2. Auth — `/api/v1/auth`

### `POST /auth/register`
- Auth: none.
- Body: `{email, password, full_name}`.
- Validation: email format + uniqueness; password ≥ 10 chars, not in a
  common-password blocklist.
- Response `201`: `{id, email, full_name, is_verified, created_at}` (no
  tokens — user must log in separately, or tokens included if
  auto-login-after-register is enabled; see `04-user-stories.md`
  US-AUTH-01).
- Errors: `409 EMAIL_ALREADY_REGISTERED`, `422` validation.

### `POST /auth/login`
- Auth: none. Rate-limited.
- Body: `{email, password}`.
- Response `200`: `{access_token, refresh_token, token_type: "bearer", expires_in}`.
- Errors: `401 INVALID_CREDENTIALS` (generic for both wrong-email and
  wrong-password), `403 ACCOUNT_LOCKED`, `429 RATE_LIMITED`.

### `POST /auth/refresh`
- Auth: none (refresh token in body is the credential). Rate-limited.
- Body: `{refresh_token}`.
- Response `200`: new `{access_token, refresh_token, token_type, expires_in}`.
- Errors: `401 INVALID_REFRESH_TOKEN` (covers expired, revoked, and reuse-detected cases — see UC-02 for the reuse-detection side effect).

### `POST /auth/logout`
- Auth: required. Body: `{refresh_token}` (or none, to revoke all).
- Response `204`.

### `POST /auth/change-password`
- Auth: required. Body: `{current_password, new_password}`.
- Response `204`. Errors: `401 INVALID_CURRENT_PASSWORD`, `422` policy.

### `POST /auth/forgot-password`
- Auth: none. Rate-limited. Body: `{email}`.
- Response `202` always (no enumeration — see security-architecture §1.4).

### `POST /auth/reset-password`
- Auth: none. Body: `{reset_token, new_password}`.
- Response `204`. Errors: `400 INVALID_OR_EXPIRED_RESET_TOKEN`.

## 3. Users — `/api/v1/users`

### `GET /users/me`
- Response `200`: `{id, email, full_name, role, default_currency, timezone, is_verified, created_at}`.

### `PATCH /users/me`
- Body: any subset of `{full_name, default_currency, timezone}`.
- Response `200`: updated profile. Errors: `422` invalid currency code.

## 4. Accounts — `/api/v1/accounts`

### `POST /accounts`
- Body: `{name, type, currency, opening_balance?}` (`type` ∈ BANK, CASH,
  CREDIT_CARD, SAVINGS, INVESTMENT, WALLET).
- Response `201`: full account object including `balance`.

### `GET /accounts`
- Query: `include_archived` (bool, default false).
- Response `200`: paginated list, plus is typically small enough to
  return unpaginated (`page_size` still honored if passed) since a user
  realistically has single-digit-to-low-dozens of accounts.

### `GET /accounts/{account_id}`
- Errors: `404 ACCOUNT_NOT_FOUND`.

### `PATCH /accounts/{account_id}`
- Body: subset of `{name, type}`. Currency is immutable after creation
  (changing it would invalidate historical transaction currency
  assumptions) — attempting to change it returns `422`.

### `POST /accounts/{account_id}/archive`
- Response `204`. Idempotent (archiving an already-archived account is a
  no-op success).

### `GET /accounts/{account_id}/balance`
- Response `200`: `{account_id, balance, currency, as_of}` — a
  lightweight, single-purpose endpoint for clients that only need the
  number.

## 5. Categories — `/api/v1/categories`

### `GET /categories`
- Query: `type` (INCOME/EXPENSE filter), `include_archived`.
- Response `200`: system categories (shared) + the caller's custom
  categories, merged.

### `POST /categories`
- Body: `{name, type}`. Errors: `409 CATEGORY_NAME_EXISTS`.

### `PATCH /categories/{category_id}`
- Errors: `403 CANNOT_MODIFY_SYSTEM_CATEGORY` if `is_system`.

### `POST /categories/{category_id}/archive`
- Errors: `403 CANNOT_MODIFY_SYSTEM_CATEGORY` if `is_system`.

## 6. Transactions — `/api/v1/transactions`

### `POST /transactions` **[Idempotent-Key optional]**
- Body: `{account_id, type (INCOME|EXPENSE), amount, currency, category_id, transaction_date, description, merchant?, notes?}`.
- Response `201`: transaction object; account balance is updated
  server-side (fetch `/accounts/{id}` or the updated balance is echoed
  in the response's `account_balance_after` field for client
  convenience).
- Errors: `404 ACCOUNT_NOT_FOUND`, `400 ACCOUNT_ARCHIVED`,
  `422 CATEGORY_TYPE_MISMATCH` (e.g., an INCOME-only category used on an
  EXPENSE transaction).

### `GET /transactions`
- Query: `account_id`, `category_id`, `type`, `date_from`, `date_to`,
  `amount_min`, `amount_max`, `search` (matches description/merchant),
  `sort_by` (`transaction_date`|`amount`, default `transaction_date`),
  `sort_dir` (default `desc`), `page`, `page_size`.
- Response `200`: paginated envelope.

### `GET /transactions/{transaction_id}`
- Errors: `404`.

### `PATCH /transactions/{transaction_id}`
- Body: subset of mutable fields. Recalculates account balance
  atomically (reverse old effect, apply new, in one DB transaction).

### `DELETE /transactions/{transaction_id}`
- Soft-delete (`is_voided = true`); reverses balance effect atomically.
- Response `204`.

### `POST /transactions/import`
- `multipart/form-data`, field `file` (CSV, max size per config).
- Response `200`: `{batch_id, total_rows, valid_rows, invalid_rows: [...], potential_duplicates: [...]}`.
- Errors: `400 INVALID_FILE_FORMAT`, `413 FILE_TOO_LARGE`.

### `POST /transactions/import/{batch_id}/confirm` **[Idempotent-Key]**
- Body: `{row_ids_to_import}` (defaults to all VALID, non-duplicate rows
  if omitted).
- Response `200` (sync, small batch): final report. `202` (async, large
  batch): `{batch_id, status: "PROCESSING", status_url}`.
- Errors: `409 BATCH_ALREADY_CONFIRMED`, `410 BATCH_EXPIRED`.

### `GET /transactions/import/{batch_id}`
- Response `200`: batch status + report (used for polling async imports).

## 7. Transfers — `/api/v1/transfers`

### `POST /transfers` **[Idempotent-Key optional]**
- Body: `{from_account_id, to_account_id, amount, currency, transfer_date, description?}`.
- Response `201`: transfer object including both resulting account
  balances.
- Errors: `404` (either account not owned/found), `400 CURRENCY_MISMATCH`,
  `400 INSUFFICIENT_FUNDS`, `422 SAME_ACCOUNT_TRANSFER`.

### `GET /transfers`
- Query: `account_id`, `date_from`, `date_to`, `page`, `page_size`.

### `GET /transfers/{transfer_id}`
- Errors: `404`.

## 8. Budgets — `/api/v1/budgets`

### `POST /budgets`
- Body: `{category_id, target_amount, currency, period_month, period_year}`.
- Errors: `409 BUDGET_ALREADY_EXISTS` (unique per category+period).

### `GET /budgets`
- Query: `period_month`, `period_year` (defaults to current month).
- Response `200`: list, each including computed `spent`, `remaining`,
  `utilization_pct`, `is_overspent` (see UC-06).

### `GET /budgets/{budget_id}`

### `PATCH /budgets/{budget_id}`
- Body: `{target_amount}`.

### `DELETE /budgets/{budget_id}`
- Response `204`.

### `GET /budgets/summary`
- Query: `period_month`, `period_year`.
- Response `200`: `{period, total_budgeted, total_spent, categories: [...]}`.

## 9. Financial Goals — `/api/v1/goals`

### `POST /goals`
- Body: `{name, target_amount, currency, current_amount?, target_date}`.

### `GET /goals`
- Query: `status` (ACTIVE/ACHIEVED/CLOSED), `page`, `page_size`.
- Response includes computed `progress_pct`, `remaining_amount`,
  `required_monthly_contribution`, `is_achieved` (see UC-08).

### `GET /goals/{goal_id}`

### `PATCH /goals/{goal_id}`
- Body: subset of `{name, target_amount, target_date}`.

### `POST /goals/{goal_id}/contributions`
- Body: `{amount, contributed_at, source_account_id?, source_transaction_id?}`.
- Response `201`: contribution object; goal's `current_amount` updated
  atomically; `is_achieved`/`status` recalculated.

### `GET /goals/{goal_id}/contributions`
- Response `200`: paginated contribution history.

### `POST /goals/{goal_id}/close`
- Response `204`. Sets `status = CLOSED` without deleting history.

## 10. Recurring Transactions — `/api/v1/recurring-transactions`

### `POST /recurring-transactions`
- Body: `{account_id, category_id?, type, amount, currency, description, frequency, interval?, start_date, end_date?}`.

### `GET /recurring-transactions`
- Query: `status`, `page`, `page_size`.

### `GET /recurring-transactions/{rule_id}`

### `PATCH /recurring-transactions/{rule_id}`
- Body: subset of mutable fields (amount, description, end_date, etc.).
  Changing `frequency`/`interval`/`start_date` after occurrences exist
  recalculates `next_run_date` but never retroactively alters already-
  generated transactions.

### `POST /recurring-transactions/{rule_id}/pause`
### `POST /recurring-transactions/{rule_id}/resume`
- Both `204`.

### `DELETE /recurring-transactions/{rule_id}`
- Sets `status = ENDED` (soft); generated transactions are untouched.
- Response `204`.

### `GET /recurring-transactions/{rule_id}/occurrences`
- Query: `upcoming` (bool) — if true, computes the next N scheduled
  dates without materializing them; else returns already-processed
  occurrences with links to their transactions.

## 11. Reports — `/api/v1/reports`

### `GET /reports/monthly-summary`
- Query: `month`, `year` (required).
- Response `200`: `{period, total_income, total_expense, net_savings, top_categories: [...]}`.

### `GET /reports/category-breakdown`
- Query: `month`, `year`, `type` (INCOME/EXPENSE, default EXPENSE).
- Response `200`: `[{category, amount, pct_of_total}]`.

### `GET /reports/balances`
- Response `200`: `{accounts: [{account_id, name, currency, balance}], totals_by_currency: {...}}`.

### `GET /reports/budgets-goals-snapshot`
- Query: `month`, `year`.
- Response `200`: combined budget utilization + active goal progress, for
  a single dashboard-style call.

## 15. Health & Metrics (unversioned, infrastructure endpoints)

### `GET /health` — liveness, no auth, no dependency checks.
### `GET /ready` — readiness, no auth, checks DB + Redis.
### `GET /metrics` — Prometheus text format, no auth in-cluster, not
publicly routed (see `observability.md` §4).
